# Эксплуатация

## 1. Первичная настройка (однократно)

| Где | Что | Значение |
| --- | --- | --- |
| Google AI Studio | API-ключ в **новом** проекте Google Cloud | секрет `GEMINI_API_KEY` |
| Telegram | бот через @BotFather, канал, бот — администратор канала с правом публикации | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (`@username` канала или `-100…`) |
| Supabase | новый проект (Free), строка **Session pooler** (порт 5432) | секрет `DATABASE_URL` |
| GitHub | репозиторий, Settings → Secrets and variables → Actions | секреты выше + `DASHBOARD_DB_PASSWORD` (≥ 20 символов) |
| GitHub | Variables | `DRY_RUN=true` на время проверки, затем `false`; по желанию `CHANNEL_NAME`, `PUBLISH_THRESHOLD` |
| Vercel | импорт репозитория; Environment Variables | `DASHBOARD_PASSWORD`, `DASHBOARD_DATABASE_URL` (роль `newsbot_dashboard`, transaction pooler 6543), `CHANNEL_NAME` |

Секреты вводятся только в настройках сервисов, никогда — в репозиторий, чат или логи.

**Почему Session pooler.** Прямое подключение Supabase Free доступно только по IPv6, а раннеры GitHub
Actions работают по IPv4. Transaction pooler (6543) не поддерживает сессионные advisory-блокировки,
которыми конвейер защищается от параллельных запусков. Session pooler (5432) — IPv4 и блокировки
работают. Workflow отказывается запускаться с портом 6543.

**Роль панели.** Первый облачный цикл выполняет `ainews grant-dashboard`: создаёт роль
`newsbot_dashboard` (только `SELECT`, `default_transaction_read_only=on`). Пароль передаётся как
SCRAM-хеш, открытый текст не попадает в логи Postgres. Имя пользователя для pooler:
`newsbot_dashboard.<project-ref>`.

## 2. Запуск и проверка

1. `DRY_RUN=true` → Actions → **news-cycle** → Run workflow. В сводке запуска (Summary) видны
   статистика и полный текст каждого подготовленного поста; в панели — те же посты со статусом `dry_run`.
2. Проверив качество, поставить переменную `DRY_RUN=false`. Посты, подготовленные в dry-run, не
   публикуются задним числом (статус `dry_run` конечный) — канал не получит «пачку» устаревших постов.
3. Повторный запуск workflow не создаёт дублей: уникальность `(target, dedupe_key)`, статусы историй,
   URL-хеши статей.

Расписание. Основной триггер — «будильник» в Supabase: `pg_cron` + `pg_net` каждые 2 часа
(`5 */2 * * *` UTC) вызывают GitHub API `workflow_dispatch` для `news-cycle`. Причина: собственное
расписание GitHub на этом репозитории теряло ежечасные слоты по 7+ часов подряд (27–28.09).
Резерв — ежечасный `schedule` GitHub; проверка `ainews due` запускает полный цикл, только если с
последнего успешного прошло ≥ 1,75 ч, поэтому двойных циклов нет. Точность до минуты не гарантируется.

Настройка будильника (однократно): создать fine-grained токен GitHub (Settings → Developer settings →
Fine-grained tokens) только для репозитория `ai-news-ru` с правом **Actions: Read and write**,
сохранить как секрет репозитория `DISPATCH_TOKEN`, затем Actions → **dispatcher** → `setup`.
Проверка: `dispatcher` → `status` (последние запуски job и HTTP-ответы GitHub, ожидается 204).
Токен хранится зашифрованным в Supabase Vault. Срок действия токена ограничен — продлить до истечения. В публичных репозиториях GitHub отключает расписание
после 60 дней без активности; репозиторий приватный.

## 3. Мониторинг

- Панель: последний успешный цикл и флаг «УСТАРЕЛО» (> 9 ч), ошибки источников, собранные и
  объединённые материалы, очередь, `uncertain`, AI-квота, компоненты рейтинга, недельная подборка,
  подписчики и реакции.
- Упавший workflow → GitHub присылает письмо владельцу. Цикл завершается ошибкой только при
  фатальных сбоях; ошибки отдельных источников и отложенный AI — штатные состояния, видимые в панели.

## 4. Telegram: неопределённый результат отправки

`sendMessage` не идемпотентен. Строка очереди переводится в `sending` и сохраняется **до** запроса.
Если ответ не получен (таймаут чтения, 5xx, обрыв, падение процесса) — статус `uncertain`,
автоматического повтора нет, очередь канала останавливается до следующего цикла.

Процедура: открыть канал → найти пост → Actions → **resolve-publication**:
`sent` (пост есть; можно указать message id), `retry` (поста нет — отправится в следующем цикле),
`cancel`. Ошибки «соединение не установлено» и 429 повторяются автоматически (ограниченно):
при 429 используется `retry_after` из ответа Telegram.

## 5. Бюджет и квоты

Цель 0 €. Платные функции не включены и не включаются автоматически.

| Сервис | Тариф | Как держим 0 € |
| --- | --- | --- |
| Gemini API | Free tier нового проекта | лимит запросов/сутки (`LLM_DAILY_REQUEST_LIMIT`, по PT), блокировка до полуночи PT после 429 «PerDay», нет автоперехода на платную модель |
| GitHub Actions | приватный репозиторий: 2000 мин/мес | ~12 полных циклов/сутки × ~3–4 мин + короткие резервные проверки ≈ 1300–1700 мин/мес (близко к лимиту; при нехватке — сделать репозиторий публичным (минуты не ограничены) или вернуть 3 часа); без способа оплаты превышение не тарифицируется, а блокируется. Счётчик: Settings → Billing |
| Supabase | Free (500 МБ БД) | ретеншн 30 дней, эмбеддинги 256-мерные, тела статей чистятся; размер БД в статистике цикла |
| Vercel | Hobby | одна функция, NullPool-подключения |

`LLM_DAILY_REQUEST_LIMIT` — это лимит **запросов**, а не гарантированный лимит расходов в евро. На
бесплатном тарифе выставлять счёт некому; если когда-нибудь включить биллинг в Google Cloud, стоимость
определит тариф модели. Фактические лимиты бесплатного тарифа Google публикует только в AI Studio
(страница Rate limit) и может менять — при нехватке квоты конвейер откладывает AI-этап
(`deferred`) и показывает это в панели, сбор продолжается.

Оценка нагрузки на цикл: 1 embed-запрос (пакет до 100 текстов) + ⌈новые истории / 20⌉ запросов
триажа + ≤ 1 запрос дедупликации + по 1 запросу на каждый публикуемый пост (≤ 15).

## 6. Резервное копирование и восстановление

- Еженедельно workflow **backup** сохраняет gzip-JSONL всех таблиц + экспорт AI Weekly как артефакт
  (хранится 90 дней). Вручную: Actions → backup → Run workflow.
- Восстановление в новую/пустую базу:
  ```bash
  export DATABASE_URL="<session pooler URL новой базы>"
  alembic upgrade head
  python -m ainews restore path/to/backup     # откажется работать, если в базе уже есть данные
  ```
  Затем обновить секрет `DATABASE_URL` и заново выполнить цикл (роль панели создастся сама).
- Supabase Free приостанавливает проекты после недели бездействия; цикл каждые 4 часа обращается к
  базе, поэтому при работающем расписании это не должно происходить. Если проект всё же на паузе —
  восстановить его в панели Supabase (Restore).

## 7. Рост базы

`prune` в каждом цикле: отфильтрованные статьи > 7 дней удаляются; статьи > 30 дней вне
опубликованных историй удаляются, у остальных чистятся текст и векторы; неопубликованные истории
> 30 дней удаляются; журналы запусков > 90 дней удаляются. Опубликованные истории, недельные
подборки и очередь сохраняются.
